# PetWorld 1-E | 암호화 로컬 백업·복원 설계

- 단계: 1-E
- 기준: Room v2 `petworld_profiles.db`, 프로필 사진 `pet_photos/`, 기록 사진, DataStore 선택 프로필·테마
- 상태: 구현 전 설계 기준. 이 문서는 기능 동작 또는 테스트 통과를 의미하지 않습니다.

## 1. 백업 범위

- Room v2 프로필 및 식사·음수·배변·활동·체중 기록 전체
- 앱 전용 저장소의 실제 참조 사진 파일과 파일명 매핑
- DataStore 설정 중 선택 프로필 ID와 테마 (기기 고유·권한·임시 상태 제외)
- SQLite의 WAL 체크포인트를 보장한 일관된 스냅샷. 실행 중 DB 파일만 직접 복사하지 않음

## 2. 파일 포맷 및 보안

- 시스템 Storage Access Framework `ACTION_CREATE_DOCUMENT` / `ACTION_OPEN_DOCUMENT` 사용, 전체 저장소 권한 요청 금지
- 단일 `.petworld` 파일: 버전 지정 헤더, KDF 파라미터, salt, nonce, 인증된 암호문
- 사용자 암호 기반 키 유도: PBKDF2-HMAC-SHA256(충분한 반복 횟수, 랜덤 salt), AES-256-GCM(파일별 랜덤 nonce)
- 암호 및 평문 키는 저장하거나 로그로 출력하지 않음. 암호 분실 시 복구 불가를 명확히 고지
- 내부 암호화 페이로드에 manifest(schemaVersion, appVersion, 각 파일 SHA-256/길이), DB 스냅샷, 사진을 포함
- 백업 암호 입력 및 확인, 저장 성공·실패 상태, 백업 파일명·날짜 표시

## 3. 복원 안전성

1. 사용자가 파일과 암호 선택. 기존 데이터가 덮어써짐을 사전 안내
2. 앱 전용 임시 공간에 복호화, GCM 인증·파일 크기 제한·경로 정규화·해시 검증
3. 지원 가능한 스키마 버전 확인, SQLite 무결성 및 외래키 검사, 프로필 UUID·사진 참조 검증
4. 현재 DB 연결과 관찰 스트림을 안전하게 중단하고 기존 DB·사진·설정을 롤백용 스냅샷으로 보관
5. 검증된 데이터와 사진을 교체하고 DB를 다시 연 뒤, 선택 프로필이 유효한지 확인
6. 어느 단계든 실패하면 원본 데이터로 롤백. 성공 이후에만 임시 파일 제거
7. 복원 과정 중 앱 강제 종료 시 다음 실행에서 완료/롤백을 판정할 복구 저널을 사용

## 4. UI

- 더보기 > 데이터 관리 > 백업 생성 / 백업 복원
- 백업 생성: 포함 항목 안내 → 암호·확인 → 시스템 저장 위치 → 완료
- 백업 복원: 파일 선택 → 암호 → 검사 결과/기존 데이터 교체 확인 → 진행 → 완료
- 오류: 잘못된 암호·변조 파일, 지원하지 않는 버전, 저장 공간 부족, 읽기 권한 취소, 손상된 사진
- 기록·프로필·사진을 포함한 전체 복원만 우선 지원. 부분 병합은 중복 ID/충돌 정책 확정 전 제외

## 5. 검증 기준

- 프로필 2마리, 기록 5종, 사진 포함 백업 → 삭제 후 복원 → UUID/수치/시각/사진 해시 동일
- 기존 v1→v2 이전 데이터 포함 백업·복원
- 비밀번호 오입력·암호문 1바이트 변경·사진 누락·잘못된 파일 경로에서 기존 데이터 보존
- 파일 저장 취소, 디스크 부족, 복원 중 강제 종료에서 원본 복구
- 라이트·다크, 작은 화면, 160% 글꼴, TalkBack, Android 26~37 확인
- CI: 단위 테스트·Lint·Debug 빌드 통과, 별도로 실제 기기 파일 선택기 QA

## 6. 개발 순서

1. 백업 manifest·암호화 codec 및 단위 테스트
2. Room 일관된 스냅샷·사진 패키징
3. 복원 검증·원자적 교체·롤백
4. DataStore 연계 및 더보기 화면
5. 통합/실기기 검증 후 PR 병합

**주의:** 현재 1-D의 실제 기기 마이그레이션 및 사진 검증도 완료되지 않았으므로 1-E 출시 전 회귀 검증에 포함합니다.

## 7. 1-E-B 구현 사항 (2026-11-09)

- `PetWorldBackupExporter.exportToStream(output, password)`: Room 트랜잭션에서 `pets`/`care_entries` 동시 조회
- `exportToUri(destination, password)`: 시스템 Document URI에 암호화된 바이트 기록 (URI 선택 UI는 1-E-D 예정)
- DataStore의 현재 `themeMode`, `selectedPetId`를 `data.json`에 포함
- DB에서 참조하는 `pet_photos/pet_*.jpg`만 중복 제거하여 수집; 참조가 깨진 경우 오류
- `manifest.json`에 포맷/스키마 버전, 생성 시각, 각 엔트리의 길이와 SHA-256 포함
- ZIP 패키징을 메모리 파이프로 AES-256-GCM 암호화 스트림에 전달해 별도의 평문 ZIP 파일을 만들지 않음
- SQLite의 WAL 파일을 직접 복사하지 않고 Room 트랜잭션에서 논리 스냅샷을 읽음
- 암호화·파일 쓰기 도중 오류가 발생하면 호출자(UI)가 미완료 문서를 삭제해야 함
- 기록과 사진 파일 사이에 동시 수정이 발생하는 경우에 대한 전체 쓰기 락/스냅샷 일관성은 후속 검증 대상

**미구현:** 암호화 파일의 실제 데이터 복원·원자적 교체(1-E-C), 저장 위치 선택/상태 UI(1-E-D), Android 실기기 QA 및 완료된 CI 결과.

## 8. 1-E-C 복원 엔진 및 예외 처리 (2026-11-09)

- `PetWorldBackupRestorer.restoreFromStream` / `restoreFromUri` 추가
- AES-GCM 복호화 전체 인증을 통과한 임시 파일만 처리
- ZIP 엔트리 경로 allowlist, 중복 엔트리 차단, 최대 엔트리 10,000개, 항목당 50MiB/전체 1GiB 제한
- manifest의 파일 수·경로·크기·SHA-256을 비교, 누락/추가 파일 차단
- Room v2 프로필/기록 JSON 재구성, 중복 ID·외래키·참조 사진·설정 값 검증
- 기존 사진과 동일 파일명이 충돌하면 해시 비교 후 다를 경우 복원 거부(원본 불변)
- 모든 Room 데이터 변경을 하나의 트랜잭션에 포함. 실행 중 오류는 트랜잭션 롤백
- DataStore 변경 오류 시 복원 전 Room 행과 DataStore 값을 재적용하는 보상 롤백 시도
- 임시 파일 삭제 및 실패한 신규 사진 복사 정리. 롤백 자체가 실패한 경우 사진은 데이터 보존을 위해 유지
- 자동 테스트: 백업→데이터 삭제→복원, 잘못된 암호/변조 파일에서 기존 레코드 불변

### 현재 제한 및 병합 조건

**중요:** Room 트랜잭션과 DataStore/사진은 하나의 원자적 트랜잭션이 아닙니다. 프로세스가 DB 커밋과 설정 저장 사이에 종료되거나 다른 화면에서 동시에 기록이 수정되는 경우에 대한 일관된 재시작 복구는 아직 구현되지 않았습니다. 호출자는 복원 중 모든 편집을 차단해야 하며 1-E-D UI에서 성공 후 Repository 새로고침을 연결해야 합니다. 앱 강제 종료 후 자동 롤백을 보증하는 기능으로 간주하거나 배포해서는 안 됩니다.

CI·실기기 검증 이전 상태로 Draft PR을 유지합니다.

## 9. 1-E-D 백업 화면 1차 연결 및 CI 오류 수정 (2026-11-09)

- Robolectric 백업·복원 통합 테스트에서 미지원 기본 SDK로 발생한 UnsupportedOperationException을 해결하도록 `@Config(sdk = [35])` 지정
- `PetBackupSection` 추가: 더보기 > 설정 > 데이터 관리
- 사용자 암호(8자 이상)/암호 확인, Android `CreateDocument`를 사용한 `.petworld` 저장 위치 선택, 백업 성공·실패 메시지
- 실패한 문서는 ContentResolver 삭제를 시도하며, 비밀번호 `CharArray`는 사용 후 초기화
- 복원 버튼은 강제 종료 후 자동 복구 저널·동시 편집 차단이 준비되지 않아 비활성화; 사용자 데이터 보존 우선
- 기존 테마 설정 및 프로필 관리 기능은 변경하지 않음

**후속 필수:** 프로세스 재시작 복구 저널, 복원 중 동시 쓰기 차단, Repository 새로고침, 실제 기기 스토리지 선택 및 사진 통합 검증. CI 성공 전 병합 금지.
