# PetWorld | 001 데이터 계약·검증·이행 계획
> 2026-11-09 · 0단계 기술/QA 기준선 v1.0 · 프로젝트 소스 아직 없음

## 1. 설계 결정(초기 기준)
- 플랫폼: Android 우선, Kotlin + Jetpack Compose + Material 3, MVVM/Repository, Coroutines/Flow, Room, DataStore.
- 기준 저장소: https://github.com/hebi10/PetWorld (main). 기능 코드·Android 프로젝트는 이 문서 작성 시점에 미구현.
- 기본 동작은 로그인 없는 오프라인. 앱 내부 저장소 사용. 서버/Firebase/AI는 조건부 추가.
- Android package/applicationId는 스토어 등록 및 서명 정책과 함께 1단계에서 최종 확정; 임의로 현재 배포 식별자가 있다고 가정하지 않음.
- 통계는 원시 기록에서 재계산 가능한 파생 데이터이며, 집계를 단일 진실 원천으로 저장하지 않음.

## 2. 논리 데이터 모델
- **Pet:** id(UUID PK), name(required), species(CAT/DOG/OTHER), breed?, birthday?, birthdayAccuracy?(EXACT/APPROX/UNKNOWN), sex?, neutered?, photoRef?, notes?, isArchived, createdAt, updatedAt.
- **PetPreference:** petId(FK unique), enabledRecordTypes, defaultUnitByType, quickActionOrder.
- **CareEntry:** id PK, petId FK(index), type(FOOD/WATER/ELIMINATION/ACTIVITY), occurredAt UTC(index), timezoneId, note?, createdAt, updatedAt, deletedAt?, authorId?, attachmentRefs. 타입별 typedPayload는 형식별 테이블/구분 컬럼 중 1단계 DB 설계에서 정합성이 높은 방식으로 확정.
- **FoodEntry payload:** kind, productId?, servedValue, consumedValue?, unit(g/mL), consumedMeasured(bool). consumedValue NULL means unknown, 0 means confirmed none eaten.
- **WaterEntry payload:** amountMl?, measured(bool). measured=false means unknown; NEVER aggregate as zero.
- **EliminationEntry payload:** kind(URINE/STOOL), count(int>=1), observation?, photoRefs?.
- **ActivityEntry payload:** kind(WALK/PLAY/SLEEP/OTHER), startedAt, durationMinutes(>0), notes?.
- **WeightRecord:** id PK, petId FK, measuredAt UTC, timezoneId, grams(integer >0), displayUnit, note?, createdAt, updatedAt, deletedAt?.
- **RecordAttachment:** id PK, ownerEntityType, ownerEntityId, privateFileRef, mimeType, size, sha256?, displayName?. No raw absolute paths exported to reports.
- **FoodProduct:** id PK, label, foodType, defaultUnit, active; 선택적 재사용 정보. 사용자의 실제 입력 기록은 제품명 변경 후에도 유지.
- **SymptomEntry:** id, petId, occurredAt, symptomType, severityText?, duration?, note?, photoRefs? (확장1).
- **VetVisit:** id, petId, clinicName?, visitedAt, reason?, summary?, relatedSymptomIds, attachments (확장1).
- **PreventiveCare:** id, petId, kind, scheduledAt, completedAt?, recurrence?, notificationPreference (확장1).
- **MedicationPlan:** id, petId, label, scheduleRule, startsAt, endsAt?, userDirectionsNote?, active, revision (확장1).
- **MedicationOccurrence:** id, planId FK, scheduledAt UTC, scheduleRevision, status(UPCOMING/DONE/SKIPPED/UNCONFIRMED/CANCELED), actualAt?, completedBy?, updatedAt. Unique(planId,scheduledAt,scheduleRevision). No automatic double-complete (확장1).
- **PetExpense:** id, petId? (null means household), amountKrw, category, paidAt, note?, receiptRef? (확장1).
- **PetMoment:** id, petId, takenAt, photoRef?, title?, note? (확장3).
- **Household / Member:** groupId, ownerUserId; userId, role, inviteStatus, joinedAt (확장2).
- **SyncRevision:** entityId, localVersion, serverVersion?, changedBy?, syncedAt?, conflictState (확장2).
- **Reminder:** linkedEntityType/id, scheduledAt, recurrence?, enabled, deliveryStatus? (확장1).

## 3. 관계 및 인덱스
- Pet 1:N CareEntry, WeightRecord, SymptomEntry, VetVisit, MedicationPlan, PetExpense, PetMoment.
- MedicationPlan 1:N MedicationOccurrence. Household 1:N Members; Household 1:N Pets(확장2 도입 시).
- 화면 조회 주 인덱스: (petId,occurredAt DESC), (petId,type,occurredAt DESC), medication occurrence unique key, (planId,scheduledAt).
- 모든 외래키 관계는 보호 데이터 삭제 정책 명시 후 적용. 프로필 비활성화는 물리 삭제가 아니며 관련 기록은 그대로 유지.
- DB 마이그레이션: 버전별 schema 테스트와 기존 백업 파일 호환 테스트 필수. 임의 destructive migration 금지.

## 4. 정확성·보안·알림 결정
- 일별 통계는 기록 당시의 지역 시간대 기준 ‘시작 이상, 다음 날 시작 미만’ 구간. 날짜 경계/서머타임/기기 시간대 변경을 테스트한다.
- 식사 제공과 섭취는 별도 값. consumed=NULL·water.amount=NULL은 0이 아님. 임의 보간 없이 데이터 부족 표시.
- 차트는 실측 점 사이 연결 가능하되 ‘측정된 날짜’ 표시; 빈 날짜에 0을 생성하지 않는다.
- 백업 파일: 버전 manifest, 레코드+첨부, 무결성 검증, 사용자 암호 기반 암호화; 복원은 임시 검증 후 DB 트랜잭션으로 적용/원상복구.
- 외부 파일 선택은 SAF/Photo Picker; 선택된 사진은 앱 소유 저장공간에 복사한 사본으로 관리. 데이터 삭제 시 첨부 정리.
- Android 13+ 알림 동의와 Android 정확 알람 접근권한 제한 고려. 일정 조회 기능은 권한 없이 정상 사용, 정시 전달 불가 시 안내. 복약은 사용자 확인만 실제 완료로 표시한다.
- Firebase 공동 돌봄 도입 때는 인증과 서버 측 권한 검증·멤버십 해제·동시 수정 정책·오프라인 큐 재전송을 별도 보안 테스트한다.
- AI 처리 경로는 기본 비활성. 명시적 opt-in 및 실제 전송 데이터 명세 없이는 사용자 자료를 서버로 보내지 않는다.

- 동물 A(고양이), 동물 B(강아지), 서로 다른 고유 ID. A의 사료 50g 제공/섭취 미측정, B의 사료 80g 제공/60g 섭취.
