# PetWorld 1-C — 온보딩·반려동물 프로필·홈 화면 구현
기준일: 2026-11-09 · 단계 번호 004 · 배포 대상: Android
원본 요구사항: 001_기능_요구사항 / 001_상세_화면_설계
전 단계: 002 Android 기반 디자인 시스템, 003 브랜드/기능 아이콘

## 목표 및 구현 범위
- 0단계 S00/S01 첫 사용·S02 프로필 등록/수정·S03 홈·S04 반려동물 전환·S16 프로필 상세/관리·S30 설정 중 프로필 관리 부분 구현.
- 사용자의 반려동물 정보가 앱을 재실행해도 안전하게 남도록 로컬 영속 저장 구현.
- 로그인을 요구하지 않는 온보딩 → 정보 등록 → 선택된 프로필의 홈 → 추가 프로필 생성/전환 → 편집/보관/복원/삭제의 순환 흐름.
- 1-A 색/타이포, 1-B 아이콘은 유지. 그림자·그라데이션·새로운 컬러 및 서비스 의존성 추가 없음.

## 사용자 플로우
1. 첫 실행에는 로컬 프로필 로딩 후 프로필이 없다면 환영 화면을 보여주고 ‘반려동물 등록’ 안내.
2. 등록: 이름 필수, 종(고양이·강아지·기타) 선택, 그 외 필드 선택. 사진은 Android Photo Picker 사용.
3. 필드 검증에 성공하면 새 UUID 프로필을 로컬 SQLite에 저장하고 ID를 DataStore에 선택 프로필로 저장.
4. 홈 헤더의 프로필 버튼에서 현재 보호 중인 동물의 목록을 확인·선택·추가하거나 관리 화면으로 이동.
5. 상세 프로필에서 편집. 수정 중 나가면 변경 내용 폐기를 확인. 저장 실패 시 양식과 입력값을 유지.
6. 보관 시 홈 선택 목록에서 제외. 보관한 동물은 관리에서 복원. 모든 프로필 보관 시 온보딩에서 관리 화면으로 진입 가능.
7. 영구 삭제는 확인 화면 2단계 후 수행. 실제 삭제 전에 대상의 이름을 보여주며 저장된 사진 사본도 제거.

## 프로필 데이터 모델
PetProfile:
- id: UUID(String) / name: 필수(공백만 불가, 최대 40자) / species: CAT,DOG,OTHER
- breed: 자유 텍스트 80자 이내 / birthday: yyyy-MM-dd 또는 NULL / estimatedAgeYears: 0~100 또는 NULL
- sex: UNKNOWN,FEMALE,MALE / neuterStatus: UNKNOWN,YES,NO
- notes: 메모 최대 2,000자 / photoFile: 앱 내부 JPEG 파일명 또는 NULL
- isArchived / createdAt / updatedAt: UTC epoch milliseconds
- 생일과 추정 나이는 동시에 저장하지 않으며, 미상일 경우 둘 다 NULL.
- 현재 나이 표기는 생일에서 계산하는 만 나이 또는 ‘약 N세 (등록 시점)’으로 구분.
- SQLite table: pets (단일 진실 원천). 프로필별 recordId와 연관할 수 있는 stable pet UUID를 후속 테이블에서 참조.
- 로컬 선택 ID는 DataStore selected_pet_id. 선택한 ID가 보관/삭제되었을 경우 활성 프로필로 표시를 전환.

## 화면 상세
S00 준비 상태: 프로필 로딩 및 재시도 표시. 불러오기 실패 시 빈 상태로 덮어쓰지 않음.
S01 처음 시작: 핵심 가치·로컬 저장·다음 단계 기능 고지, 등록 CTA, 보관한 프로필이 있다면 관리 진입.
S02 프로필 입력: 사진/이름/종/품종/나이/성별/중성화/주의사항. 빈 이름·미래 생일·범위 밖 추정 나이 차단.
S03 홈: 날짜, 프로필 이름/사진·종/품종·나이, 주의사항, 식사·음수·배변·활동·체중 상태, 최근 기록 섹션. 기록은 아직 없으므로 ‘기록 없음’으로 표시.
S04 전환 시트: 활성 프로필 목록, 현재 선택 체크, 48dp 이상 터치 영역, 추가/관리 버튼.
S16 관리: 전체 프로필, 수정/보관/해제/영구 삭제. 삭제 이중 확인. 보관은 데이터 삭제가 아님.
S30 더보기: 프로필 개수/추가/관리 및 기존 시스템·라이트·다크 테마 선택.

## 예외 정책
- 이름 공백/길이, 생일 미래/범위, 나이 0~100, 사진 크기 20MB 상한, 이미지 Decode 실패를 사용자 메시지로 안내.
- 사진 URI는 선택 후 저장 시점에만 복사, 앱 소유 저장소 내부 JPEG로 재인코딩(대형 이미지는 1200px 정도로 샘플링), EXIF 등 원본 메타데이터 보존하지 않음.
- 사진 권한 거부 또는 선택 취소 시 사진 없이 프로필 작성 가능.
- SQLite 오류나 저장 실패 시 화면이 닫히지 않고 입력을 유지. 사진 복사 실패 시 DB 변경 없음.
- 앱의 로컬 저장소만 사용. 앱 자동 백업 off이므로 삭제/기기 이전 시 백업이 아직 없다는 점을 명시.
- 수치 '0'은 자동 기록하지 않으며 미측정 데이터를 실제 기록으로 오인하지 않음.
- 전화기 360dp·글꼴 160%·태블릿 및 테마 QA 필요. 실제 캡처는 CI 빌드와 별개.

## 1-D 확장 지침
- Room DAO/Table 도입 시 PetProfile UUID 유지; 기존 SQLite `petworld_profiles.db` 데이터를 깨끗한 상태로 보존하도록 이관/스키마 검증·마이그레이션 테스트 실시.
- 실사용 데이터가 있는 환경에서 destructive migration 절대 금지.
- 새 기록 엔터티는 반드시 petId FK 참조하며, 프로필 보관/삭제 시 기록 영향도를 안내해야 함.
- 일상 기록이 구현되기 전에는 기록 추가/통계 집계 버튼을 동작하는 것처럼 노출하지 않음.

## 테스트 기준
- A 새 설치: 환영 → 새 프로필 작성 → 홈 → 앱 재실행 → 동일 데이터.
- B 다중: 고양이와 강아지 각각 저장→선택 전환→서로의 기본값 구분.
- C 필수값: 이름 누락·미래 생일·잘못된 추정 나이는 저장 안 됨.
- D 사진: 선택/취소/제거, 앱 재시작 시 보존, 다른 프로필 사진 영향 없음.
- E 관리: 수정·보관·복원·삭제, 마지막 동물 보관→온보딩에서 관리 접근.
- F 상태: DB 로딩 오류와 저장 실패 안내, 미저장 이탈 확인.
- G 디자인: 360dp/160% 글꼴·시스템/라이트/다크·TalkBack·태블릿.
- H CI: :app:testDebugUnitTest, :app:lintDebug, :app:assembleDebug 모두 성공.
- I 실제 기록/통계 값과 동기화·백업은 별도 단계 완료 전 금지.
