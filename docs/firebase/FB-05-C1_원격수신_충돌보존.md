# FB-05-C1 — 원격 페이지 수신 및 충돌 보존 기반

- 기준: FB-05-B3 Draft #59, HEAD 98874b9b6e78ab613fd96caa3cda183bc9d87188. 개발 APK 실서버 QA 전 별도 스택.
- Room v3→v4는 sync_inbound 테이블·고유 인덱스만 추가한다. 이전 프로필/기록/Outbox 데이터 및 논리 백업 schemaVersion=2 보존. v1/v2/v3 마이그레이션 회귀 테스트.
- FirebaseDev 전용 server-only reader: 현재 Google 계정 해시/개발 환경/검증된 permission/온라인 토큰/ready migrationState 확인. 문서 ID 커서와 최대 100건, 캐시·미확정 로컬 쓰기 제외. 일반 앱·Worker에서는 호출하지 않는다.
- 전체 페이지의 계정·경로·UUID 중복·스키마·정수/NULL·enum·날짜·측정값을 검증한다. 미지원/불완전 페이로드는 페이지 전체 거부. 전역 쓰기 잠금과 한 Room 트랜잭션에서 반영하며 계정 권한이 도중 철회되면 rollback.
- 일치한 데이터 또는 신규 식별자는 baseline 기록. 기존 데이터 수정은 이전 baseline과 현재 로컬 내용 일치·높은 revision·미전송 변경 없음이 확인된 경우만 적용. 단순 updatedAt 비교 금지. 기존 UUID 충돌·같은 revision 다른 내용·미전송 변경은 양쪽 JSON과 별도 상태 보존. 오래된 페이지와 정확한 중복 무시.
- 부모의 검증된 baseline이 준비되기 전 자식 기록을 적용하지 않는다. 모든 원격 tombstone은 DELETE_REVIEW로 남겨 자동 삭제하지 않으며 이후 되살리기도 차단한다. 사진 참조가 있는 항목은 FB-06 검증까지 보류. 원격 적용은 로컬 outbox를 새로 생성하지 않는다.
- C1은 페이지 수신 및 보수적 반영/충돌 보존 기반. 영속 커서와 반복 스캔·서버 수신과 sender/receipt baseline 연결, tombstone 승인·자식 정리, 충돌 해소 UI, 프로필 화면 자동 갱신/사용자 동의 및 WorkManager 활성화는 후속 C2/D. 데이터 누락 방지를 위해 전체 스캔 반복 정책이 필요하며 revision 단독 글로벌 커서는 사용하지 않는다.
- 실제 서버 읽기·쓰기/Rules 게시/Play 배포 없음. #55~59 보존, 신규 CI 및 실서버 QA 전 main 병합 금지.
