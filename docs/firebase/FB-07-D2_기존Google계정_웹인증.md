# FB-07-D2 — 기존 Google 계정 전용 웹 인증·1회용 챌린지

선행 #83 HEAD 5b266ecf99088fc5094a806db0e46eabf1231857. #81의 메모리 캐시 리스너 보완 후 격리 Android SDK QA 성공, #82 최신 로컬 E2E/Rules/Android 검증 성공, #83 웹/서버 Rules 및 E2E 성공. 새 변경의 CI 결과는 별도 확인해야 한다.

- 일반 Firebase Google signIn은 신규 계정을 생성할 수 있으며 Identity Platform의 autoCreate는 deprecated이다. 삭제 전용 웹 경로는 Firebase 로그인/계정 생성/연결/Custom Token 발급을 하지 않고 Google Identity Services의 ID 토큰을 공식 Google Auth Library verifyIdToken으로 검증한다. Google의 서명, audience, issuer, expiry, nonce 및 최근 인증 시각 auth_time을 확인한다. 기존 Firebase Admin getUserByProviderUid('google.com', sub)의 정확한 Google subject만 사용한다. 이메일 기반 매칭 금지, 미등록/비활성/다른 계정 거부. 서버 요청 단계에서 expected job ID 및 Firebase revocation 시각 확인, 기존 Admin lock 및 scheduler 재사용.
- /account-deletion/web-auth의 challenge/identify/submit은 별도 검증된 Web App Check ID와 exact HTTPS Origin 및 트랜잭션 rate quota가 필요하다. Android App Check ID는 web-auth 사용 불가, Web ID는 기존 Firebase Android request 사용 불가, status는 기존 ticket 계약 유지. 모든 요청/응답의 body·header·길이 및 경로 제한을 유지한다. Google ID token은 authorization header에서만 받아 검증한다. identify는 job ID만 반환하며 UID, ID token, refresh token은 반환하지 않는다. 별도 공개 worker 없음.
- nonce는 256-bit 무작위, SHA-256 digest만 Firestore accountDeletionWebChallenges 문서 ID로 저장. 목적/대상 job/생성/만료 시각, 5분 TTL. Admin 트랜잭션으로 1회 소비 및 만료/재사용/다른 목적/다른 job 거부. 실제 Firestore TTL policy 설정과 검증은 별도 필요, 만료 시점은 소비 코드 자체에서도 검증한다.
- 웹 UI는 검증된 GIS 라이브러리가 제공하는 명시적 버튼으로 Google credential을 요청하며 auto_select/One Tap 자동 호출 없음. submit 단계에서 essential_claims: 'auth_time, amr' 요청. 브라우저의 claim 해석은 참고용이고 서버가 별도 검증한다. Google auth_time이 없는 경우 또는 5분 이내 인증이 아니면 제출하지 않는다. 실제 Google security bundle 사용 가능 여부와 사용자 재인증 UX를 검증해야 한다. 기존 AES-GCM 복구 파일, 같은 job/ticket 및 응답 유실 복구 유지. 실제 FirebaseAuth 세션/credentials 생성 없음.
- Google Auth Library 11.3.4 고정 의존성 추가(공식 ID token 검증 필요). 서명 회귀는 자체 생성한 합성 RSA 키로 공식 라이브러리의 JWT 검증·변조 거부를 테스트하며 실제 Google 인증/JWKS 통신을 대신하지 않는다. 단위/경계/브라우저 계약 10개와 Rules/실제 Admin transaction 2개 추가. 기존 Android/Web 회귀 유지. CI 성공 전 완료 처리 금지.
- 실제 Web App ID/client ID/authorized origin 설정, GIS security bundle auth_time, App Check, CSP 및 same-origin hosting, TTL, 실제 OAuth/브라우저/기기 검증, IAM/Storage 보존·worker 실행 및 공유 legacy cache 확인은 미완료. 기본 preview는 script 미연결/버튼 disabled, 새로운 web admission은 별도 readiness 필요. 실제 계정 삭제·서버/웹/Play 배포·main 병합 없음.
- 다음은 신규 CI 검증 및 실제 개발 환경에서의 승인된 인증/보존 증빙, 웹 실제 화면 검증, FB-08 QA와 전체 통합. 활성화를 추정하거나 readiness 값을 임의 true로 변경하지 않는다.
