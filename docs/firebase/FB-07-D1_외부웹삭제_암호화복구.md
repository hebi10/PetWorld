# FB-07-D1 — 외부 웹 계정 삭제 요청·암호화 복구

선행 #82의 로컬 E2E 1/1 및 Rules/서버 58/58 성공(이전 HEAD 948a1b4a). #81 오프라인 쓰기 테스트의 cache miss를 기본 메모리 eager GC의 가능성과 대조해 활성 query를 유지하고 서버 확인 후 해제하도록 수정했다. #82 서버 변경은 수정된 #81 위로 정렬했다. 신규 SHA 결과 확인 필요.

- account-deletion-client.mjs: 동일 HTTPS origin의 두 고정 POST 경로, verified App Check token, no-store, redirect/error response 거부, 최소 receipt 및 상태 역행 차단, 전송 직전 계정/페이지 generation 확인. 기존 요청의 다른 티켓 생성 및 다른 계정의 제출 차단. 응답 유실 시 같은 복구 티켓을 사용한다.
- 256-bit 무작위 상태 capability는 AES-256-GCM/PBKDF2-SHA256(600,000회, random salt/IV) 암호화된 최대 2KB recovery JSON으로 내보낸다. 비밀번호 12자 이상, UID·이메일·Firebase ID token을 파일에 기록하지 않는다. localStorage/sessionStorage에 capability를 저장하지 않는다. 사용자가 저장 확인 후 명시적 삭제 승인·최근 동일 Google 계정 재인증을 해야 request를 보낸다. Auth가 삭제된 경우 recovery 파일+비밀번호+App Check로 status만 확인할 수 있다. 파일 분실 시 상태 조회 보장 없음. 브라우저/XSS/공유기기 보안 검토는 별도.
- account-deletion-firebase.mjs: 실제 Firebase Web SDK의 reauthenticateWithPopup/getIdTokenResult/getToken 및 동일 dev app 검증을 사용하는 adapter. 별도 검토된 기존 계정 전용 로그인·memory Auth·App Check·same-origin·recovery readiness가 모두 있어야 런타임을 만든다. 일반 signInWithPopup은 신규 Firebase 계정을 생성할 수 있으므로 무조건 호출하지 않는다. 기존 계정 전용 로그인 구현/검증, 실제 Web App 등록/초기화, bundling/hosting, HTTPS·CSP/App Check/authorized domain 및 실제 브라우저 검증은 미완료.
- account-deletion-preview.html 및 page module: 요청 및 복구 UI와 이벤트 연결 구현. 기본 정적 HTML에는 script 실행이 없고 모든 인증/요청/복구 버튼이 disabled. 별도 검증된 bootstrap을 연결할 때만 동작한다. 비밀번호/상태는 브라우저에 영구 저장하지 않고 화면 이탈 및 계정 전환 시 정리한다. Google 계정 자체, Guest/다른 계정/외부 백업은 삭제하지 않는다. 앱의 기존 실제 삭제 요청 차단은 유지한다.
- 서버: 기존 Android App ID allowlist 유지, 별도 Web App ID 목록과 정확한 Origin 확인 추가. Origin은 Auth/App Check를 대신하지 않는다. 추가 Web readiness 4종 없이는 서버 bootstrap에서 Web admission 활성화 거부. 공개 worker route/CORS 완화 없음. 실제 웹 서버 기동/도메인/공개 링크/배포 없음.
- 웹 회귀 10개: 암호화 복구·변조·비밀번호 오류·재인증·타 계정·응답 유실·phase 역행·HTTPS/no-store/redirect 옵션·별도 App Check allowlist·비활성 초안. 기존 Firebase CI에 편입했다. 실제 Chrome UI/Google OAuth/App Check와 서버 연결은 미검증.
- 다음: #81/82/신규 PR 검증, 기존 계정 전용 웹 로그인 및 dev 환경 실제 IAM/Storage retention/App Check/HTTPS/worker 검증, 기존 설치 공유 캐시 대조 및 기기 PIN/Keystore/정리 조건과 복구 슬롯 해제 검증. FB-08 및 최종 통합 QA와 실제 공개 삭제 URL·Play 정책 증빙은 미완료. 현재 채팅에서 실제 Firebase 관리 도구는 노출되지 않았으며 별도 배포 승인이 필요하다. main 병합/실제 사용자 삭제/Firebase·웹·Play 배포 없음.
