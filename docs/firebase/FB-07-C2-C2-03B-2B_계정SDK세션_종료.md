# FB-07-C2-C2-03B-2B — 계정별 SDK 세션·재시작 경로 보호

선행 #79 HEAD 1f8cbfa8f6d65991086ec7e639951e928608e8a6. #78 수정본과 #79의 적용 대상 Android·계정 UI·격리·배포 안전성 CI 성공(비대상 UI10G skipped). 실제 사용자 삭제·서버/웹/Play 배포 없음.

- AccountSdkRouteGate와 AccountSdkRouteJournal: 정확한 계정별 명시적 named SDK 전환 예약을 공유 route 차단과 함께 유지한다. session generation 및 RESERVED/ACTIVE/RETIRED 검증, 다른 계정 영향 방지. noBackup AtomicFile에 해시 계정 키의 경로 marker 저장. 재시작 후에도 legacy 자동 복귀 차단, 미확인/손상 marker를 덮어쓰지 않음. marker는 전환/삭제 완료 영수증이 아니다. 자동 해제/복구 정책은 미구현.
- FirebaseDevAccountSdkSessions: 검토된 캐시 전환 증거와 동일한 petworld-dev FirebaseOptions, 계정 키 named app, 기본/별도 Google UID 일치 및 두 실제 토큰 갱신 확인, 이전 account cloud 작업 0건, journal 차단 여부를 요구. 이미 별도 로그인된 SDK를 인수하는 opt-in 경계이며 새 로그인·FirebaseApp 생성·인증 정보 복제 또는 사용자 생성은 하지 않는다. 현재 계정 UI/worker는 자동 open하지 않는다. auth 변경 시 즉시 route retire. 이후 새 어댑터에서 binding을 선택하며 이전 legacy binding도 account route fence로 차단한다.
- RemoteReader, SyncTransport, PhotoStorage, FirstImportService는 동일한 선택 binding의 Auth/Firestore/Storage를 사용한다. worker admission도 route 검증. 기존 계정/권한/journal/Task 추적 및 원본 보존 유지. 명시적 isolated session이 없고 이전 marker도 없는 계정은 기존 legacy 경로 유지. 별도 route가 예약/종료된 계정은 default SDK로 fallback 금지.
- 종료: route retire → 신규 cloud work 차단 및 exact account worker revoke → 실제 task/worker/import/review drain → 해당 named 사용자의 waitForPendingWrites 성공 → 동일 계정 및 drain 재확인 → named Firestore terminate 성공 → named Auth signOut 확인. 총 45초 waiter 한도, drain 20초. timeout/cancel/SDK 오류 시 UNCONFIRMED, 임의 재시도/credential clear 금지. waitForPendingWrites는 현재 사용자만 대상으로 하며 terminate는 pending writes를 취소하지 않는다. 기존 shared persistence와 다른 named account는 변경하지 않는다. 일반 로그인/로그아웃 화면에 실제 isolated session 생성/종료를 활성화하지 않았으며, named 인증·계정 전환/종료 UI 통합은 별도 검증 필요.
- 테스트: route/종료 단위 7개 및 FirebaseDev Android smoke 2개 추가. 실제 SDK 설정/서로 다른 named/default 인스턴스 및 미검증 open 차단, noBackup marker 재인스턴스 복구와 타 계정 보존 확인. 합성 fixture만 사용하고 실서버 데이터에 쓰지 않는다. 실제 로그인 계정 A/B/Guest, offline pending writes와 재실행, 기존 설치 legacy cache inventory/reconciliation, 실제 기기 PIN/Keystore/종료/restore 검증과 UI/Room/image/listener drain·복구 슬롯 해제는 남아 있다. 기존 UNVERIFIED_SHARED 및 실제 삭제 요청 차단 유지.
- 다음: 새 Draft CI 결과 확인 후 격리 dev 환경에서 필요한 실제 named Google 인증·캐시/미전송 자료 보존 증거와 정리 조건 검증. 미검증 기존 설치에서 자동 전환 또는 일괄 삭제하지 않는다. 실서버 E2E·외부 웹 계정 삭제·FB-08·최종 통합 QA는 미완료.
