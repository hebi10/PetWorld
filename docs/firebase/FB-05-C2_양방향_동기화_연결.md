# FB-05-C2 — 양방향 동기화 연결 및 검토 기반

- 선행 Draft #60 HEAD 14923743050c349b83e7d8a05a5096f31b1c7151. Room v4→v5는 계정별 sync_scan 진행 테이블만 추가. v1~v4 마이그레이션과 기존 Outbox/Inbound 데이터 보존 검증.
- 서버 페이지 반영·커서는 한 트랜잭션에서 저장. 루트 프로필 페이지 후 각 부모의 기록 페이지를 순서대로 처리, 중단 후 동일 계정/저장된 부모 및 커서로 재개. 완료한 라운드만 명시적으로 다음 전체 스캔 시작 가능. 단일 스캔을 전체 변경의 영속 증분 커서로 간주하지 않는다.
- FIFO 전송 헤드는 server-only 단일 문서 조회로 현재 값/리비전 검증. CREATE는 실제 부재와 기존 기준 없음, UPDATE/DELETE는 수신 baseline 또는 ACK 결과의 정확한 revision/내용 일치 필요. 미확인 baseline은 대기, 불일치는 양쪽 snapshot 보존·충돌 상태. 불명확한 서버 응답은 기존 receipt 기반 재시도를 유지.
- 검증된 dev worker의 내부 경로에 전송 준비→전송→최대 10페이지 수신을 연결. 계정/permission 재검증 및 서버 캐시 배제. 실제 activate/enqueue 호출과 자동 스케줄/반복 스캔 정책은 아직 비활성.
- 명시적 acceptRemote 검토 API: 현재 서버 digest·revision 및 사용자가 본 로컬 값 재확인. 사진/tombstone/부모 미검증/이미 시도했거나 결과 불명인 전송 거부. 명확히 미전송된 항목만 SUPERSEDED 처리(삭제하지 않음), 원격값과 로컬 충돌 자료 보존. 실제 선택 UI, keep-local 재기준화·tombstone 처리, 사진 및 프로필 Flow 갱신은 후속 작업.
- 검증: 페이지 재개·다른 계정 커서 격리·다음 스캔·잘못된 페이지 원자 rollback·ACK 후 연속 전송·충돌 보존·승인·시도된 전송 폐기 차단. 실제 서버/Rules 게시/Play 변경 없음. 실서버 QA 및 선행 PR 통과 전 병합 금지.
