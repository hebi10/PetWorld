# FB-07-C2-C1 — 삭제 요청 전송 및 저장 상태 표시 준비

선행 #73 b0ecf3ff663157e4c0d51044ebb706d59ae0b08c. 실행 가능한 서버 주소, App Check 발급기, 실제 배포된 listener가 없으므로 실제 요청 버튼은 비활성 유지한다.

- 내부 DeletionProtocolTransport: 별도 검증된 HTTPS DNS origin(고정 request/status 경로, 임의 URL·query·userinfo·port 금지), fresh ID token과 App Check header, 256-bit canonical status ticket, POST/엄격한 JSON 요청 및 응답 계약(202/200, no-store, 최대 2048B, job ID와 phase만). 상태 조회의 job ID 일치, controller의 동일 계정/상태 역행 검증 유지. redirect/오류는 완료가 아닌 불확실 상태. 인증 정보/티켓/응답 본문을 화면/로그에 남기지 않는다.
- FirebaseDev HTTPS adapter는 표준 TLS 및 hostname 검증, 리디렉션/캐시 금지, 연결/읽기 제한, 응답 크기 제한을 사용한다. 정상 응답만 읽으며 운영 endpoint/자격 정보는 코드에 추가하지 않음. 장시간 SDK/연결 취소의 운영 검증 별도.
- FirebaseDevDeletionCoordinator: 사전 readiness, 대상 계정, 현재 Google 사용자 동일성, 동기화 lease 해제, 동일 계정 재인증 및 5분 토큰 확인 후 기존 encrypted journal controller 사용. 현재 UI에서 생성하거나 호출하지 않는다. 서명/제출 승인과 실제 App Check provider, 전송 전 기존 요청 drain 등은 후속.
- 로그인 계정 화면에서 해당 계정 journal의 마지막 저장 상태만 표시(서버 실시간 아님). 로딩/불확실/정상 미요청을 분리. 조회 실패 또는 다른 계정이면 cloud UI 차단, 서버 COMPLETE는 서버 삭제 완료만 의미. 저장 상태 다시 확인은 로컬 읽기이며 실제 요청·캐시 정리 없음. 비회원에게 타 계정 티켓/목록 표시 금지. 인증 삭제 후 안전한 기기 인증·상태 조회 경로는 별도 검증 필요.
- 테스트: 미검증 origin 및 임의 URL, App Check 누락, 고정 HTTP 계약, 응답 코드/형식/크기/다른 job/상태 오류, 로컬 journal 표시와 계정 격리. 실제 HTTPS/인증 연동 및 SDK 공유 캐시/quiescence 검증, HTTPS listener/queue/scheduler 등록, 앱/웹 요청 활성화는 미완료. main/실계정 삭제/Firebase/Play/웹 배포 없음.
