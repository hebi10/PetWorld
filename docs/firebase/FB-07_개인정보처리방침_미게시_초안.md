# FB-07-A — Firebase 계정 삭제·개인정보 안전 기반 (미게시 초안)

## 사용자 범위
기존 배포 개인정보처리방침은 로컬 전용 앱을 설명한다. 이 초안은 Firebase 기능이 활성화된 미래 버전의 개정 준비 자료이며 공개 정책 페이지를 변경하지 않는다. 실제 Google 로그인·Storage·Firestore 동기화 적용 전 처리 범위, 운영자 표시, 처리위탁·국외 이전, 보유 기간, 연락처 및 웹 요청 링크를 검증한다.

- 비회원: 계정 생성 없음. 기기 내 프로필·기록·사진·설정, 수동 암호화 백업의 보유/삭제 안내.
- 로그인: 인증 식별자·선택된 계정 정보, 반려동물 프로필, 기록, 사진, 동기화 상태 및 변경 이력. 자동 전송은 검증 및 동의 이후만. 인증/클라우드 제공을 위한 Google Firebase 사용, 전송 보호 및 Firebase 저장 보안. E2EE로 표시하지 않는다.
- 로그아웃은 탈퇴가 아님. 비회원 데이터와 계정 캐시는 분리. 기기의 외부 .petworld 파일은 앱이 원격 삭제할 수 없음.
- 계정 삭제: 앱과 외부 웹에서 본인 인증 및 명시적 삭제 요청. 재인증 후 삭제 시작, 중단/재시도 상태 제공. Firestore 하위 컬렉션·receipt·manifest·Storage·Auth 확인. 완료는 실제 검증 결과에만 사용한다. 삭제 잠금만으로 탈퇴 완료라고 표현하지 않는다.
- 탈퇴 전 사용자 확인, 다운로드 또는 백업 선택지, 미전송 기록 손실·기기 캐시 처리 안내. 완료까지 로컬 자동 업로드 차단 및 데이터 분리. 개인 데이터 및 인증 정보 로그 금지.
- 보유 기간 및 삭제 후 lock/job 최소 정보 보유 필요성·기간은 실제 보안/법적 근거와 함께 결정. 버킷 soft delete/versioning/보존 잠금, 과거 공유/다운로드 토큰·기기 캐시·백업 범위도 점검. 현재는 미확정 상태로 두고 운영 정책에 허위 기간을 게시하지 않는다.
- Google Play User Data 정책: https://support.google.com/googleplay/android-developer/answer/10144311
- Storage/Firestore 교차 Rules 및 추가 비용·IAM: https://firebase.google.com/docs/storage/security/rules-conditions

## 구현 단계
FB-07-A: Admin 전용 계정 삭제 잠금, Firestore/Storage 차단 및 서버 삭제 상태 머신·오프라인 테스트. 신뢰된 인증/영속 job/lease/작업 실행 adapter 계약.
FB-07-B: 실제 서버 SDK adapter, 재인증 토큰 검증·idempotent 요청 API, 폐기 가능한 테스트 계정의 하위 데이터/파일/Auth 전체 삭제 및 실패 복구 검증. IAM/App Check·과금·보존 정책 승인 전 배포 금지.
FB-07-C: 앱 탈퇴 화면 및 외부 요청 페이지, 상태 추적, 계정별 기기 캐시 정리 및 사용자 고지. 실제 검증 후 개인정보처리방침·Data safety·계정 삭제 URL 갱신.
