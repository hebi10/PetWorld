# FB-05-B1 — 전송 상태 머신·리비전 비교·재시도 계약

- 선행: FB-05-A Draft #56 `cdf613d63da6a3592dcf3f052d384e54e6dc91b2`. 실제 서버 QA 전 독립 스택.
- 계정별 FIFO Outbox, WAITING_BASELINE → READY → IN_FLIGHT → ACKNOWLEDGED/RETRY/CONFLICT/BLOCKED. 이전 미확정/충돌/차단 항목이 있으면 다음 항목의 순서를 건너뛰지 않는다.
- 서버 미존재를 직접 검증한 CREATE만 expectedRevision=-1. UPDATE/DELETE는 검증한 기존 revision ≥0. null은 미확인 상태이며 전송 금지. READY 전환 API는 후속 기준선 검증 제어기에 연결하며 현재 앱에서 호출하지 않는다.
- immutable opId, 계정 key, 작업/대상/리비전/스냅샷으로 SHA-256 요청 지문. 서버 트랜잭션은 기존 receipt를 먼저 확인하며 같은 요청이면 중복 쓰기 없이 ACK, 다른 요청이면 충돌. 새 요청은 수정 전 전체 필드 및 revision 일치 시에만 기록과 receipt를 원자적으로 저장해야 한다.
- DELETE는 기존 기록의 필드를 유지한 tombstone 문서로 변환. tombstone에 새 변경을 자동 적용하지 않는다. 사진 참조가 바뀌는 요청은 FB-06 전까지 BLOCKED.
- 로컬 claim 및 완료는 accountKey/opId/attempt 기반 CAS. 응답 유실은 RETRY, 취소 또는 계정 전환은 IN_FLIGHT 유지. 재실행 시 동일 opId 및 지문으로 복구. 지수 백오프 30초~6시간, 최대 100회 이후 중지.
- 기본 권한은 항상 false. Guest/다른 계정/동의·검증되지 않은 기준선/복원 중 전송 금지. 실제 인증 세션·기준선 승인·복원 상태 확인을 제공하는 컨트롤러, Firestore 트랜잭션 adapter와 Rules/receipt 검증, WorkManager 스케줄링은 FB-05-B2 이후 연결. 이번 PR에는 자동 호출이나 Firebase SDK 네트워크 접근이 없다.
- Room 스키마/백업 포맷 및 Play 설정 변경 없음. 단위/Room 회귀는 응답 유실, 중복 전송, 계정 전환, revision 충돌, tombstone, NULL/0, 순서/재시도 제한을 가짜 transport로 검증한다. 실제 Firebase 통합 성공으로 간주하지 않는다.
