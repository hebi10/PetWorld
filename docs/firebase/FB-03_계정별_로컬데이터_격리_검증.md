## 1. 현재 상태와 핵심 보안 결정

- Guest는 기존 Room v2 `petworld_profiles.db`와 `pet_photos` 및 `selected_pet_id`를 그대로 사용한다. 기존 사용자에게 로그인 강제/기록 복사/삭제를 하지 않는다.
- 로그인 계정의 FirebaseAuth UID는 파일·디렉터리·선택 설정에 평문으로 사용하지 않는다. UTF-8 원문 UID를 SHA-256으로 해시한 64자리 hex 값으로 파일 경로와 DataStore의 **계정별 선택 프로필 키**를 구성한다.
- 계정 A의 Room DB, JPG 사진 디렉터리, 선택 프로필은 계정 B나 Guest의 값과 분리된다. 계정별 공용 테마 `theme_mode`는 기존 공통 사용자 인터페이스 환경 설정을 유지한다.
- 로그인한 뒤에도 Guest 프로필·기록·사진은 계정 DB에 **자동 복사되지 않는다**. FB-04에서 사용자 선택과 무손실 검증 절차에 따라 최초 데이터를 복사한다.
- `PetWorldRecoveryJournal`과 Guest 암호화 백업/복원은 기존 Guest DB에 대해서만 허용한다. 로그인 계정에서 기존 Guest 복원 버튼을 숨기고, ViewModel에 실행 방지 가드를 두어 Guest 백업 데이터를 계정 DB에 적용할 수 없게 한다.
- 클라우드에 데이터를 전송하는 코드나 Firebase 보안 규칙 변경은 포함되지 않는다.

## 2. 변경 범위

### LocalAccountScope
- `Guest`: `petworld_profiles.db`, `pet_photos`, `selected_pet_id`
- `SignedIn(uidHash)`: `petworld_account_<sha256>.db`, `pet_photos_accounts/<sha256>`, `selected_pet_id_account_<sha256>`
- UID가 공백이면 계정 스코프 생성을 거부한다. 해시 기반 파일 경로는 UID 원문을 포함하지 않는다.

### Room/Repository/Theme
- `PetWorldDatabase.get(context,scope)`: DB명별 별도 Room 인스턴스, 기존 Guest get(context) 호환 유지, 명시적 closeScope(scope) 제공.
- `PetRepository`/`CareRepository`: 동일 scope의 `PetPhotoStore`를 사용하며 레거시 Guest 기본값 유지.
- `ThemePreferences`: 테마는 기존 공통 값, 선택 프로필 ID는 scope별 DataStore key로 분리.
- `MainViewModel.factory(context,scope)`: DB/Repo/Photo/선택 프로필 주입을 scope별로 구성. 계정 DB에서 기존 Guest 복원 API 호출 차단.

### FirebaseDev identity & lifecycle
- 개발 빌드 전용 비공개 `FirebaseDevAccountScopeProvider`는 앱 시작 시 `LocalAccountScopeResolver`를 등록한다.
- 실행 패키지 `com.haebi.petworld.dev` 및 Firebase 프로젝트 `petworld-dev`가 확인될 때만 FirebaseAuth의 현재 사용자를 scope로 변환한다. 개발 초기화 실패 시 Guest로 추측 전환하지 않고 오류 표시.
- `MainActivity.onResume`에서 이전 identity와 현재 identity가 다르면 이전 ViewModel·Room 연결을 정리하고 새 Activity에서 해당 scope의 자료를 표시한다.
- Google 로그인/로그아웃이 계정 UI에서 진행되어도 복귀 시 이전 계정의 Flow/썸네일/선택 이력을 그대로 보여주지 않도록 Activity를 교체한다.

### FB-02 실계정 재검증 경로
- 개발용 계정 UI에 `실제 Firebase 인증 확인` 버튼을 추가한다. 로그인된 계정에서 Firebase ID 토큰을 네트워크로 강제 갱신하고, 인증 SDK의 현재 계정 UID가 변하지 않았는지 확인하여 성공/실패 상태만 표시한다.
- 인증 토큰/UID/암호는 로그 또는 UI 출력하지 않는다. 계정 이메일은 사용자가 이미 선택한 자신의 계정 연결 상태에만 표시할 수 있다.
- **이 버튼의 실기기 실행 결과는 아직 없다.** 과거 PR #31의 고정서명 SHA 검증은 본 PR 소스의 실기기 Google 로그인 증거를 대체하지 않는다.

## 3. 테스트 및 완료 판정

### Local JUnit
- Guest DB·사진·선택 ID 경로의 이전 버전과 정확한 일치
- 서로 다른 UID의 SHA-256 경로 독립성과 원문 UID 비노출
- 빈 UID 거부·30회 계정 결정성 확인

### Android Instrumentation (API 29·35·36)
- Guest 원본 DB의 기존 pet/record ID 목록을 먼저 읽고 테스트 후 동일한지 확인
- 임의 계정 A·B 각각 2마리, 식사/음수/배변/활동/체중 5종 기록 생성·조회
- 동일한 JPG 파일명이더라도 A/B 저장 디렉터리가 서로 다르고 내용이 격리됨을 확인
- 계정별 selectedPetId 독립, 30회 교차 DB 재조회에서 이전 계정 기록 노출 없음
- 테스트 계정 해시 경로만 삭제하고 Guest DB·사진·선택 설정 변경하지 않음

### 기존 기능 회귀
- Android CI Unit/Lint/Debug; 비회원 레거시 백업/복원 Emulator QA
- Android dev AccountActivity UI QA 및 기존 설정·퀵 기록·키보드·반응형·폴더블 QA

## 4. 실제 검증에 필요한 접속/기기

Google 계정 선택 → 앱에 로그인 → `실제 Firebase 인증 확인` 버튼 성공 → 메인 계정 전환 → 계정 A/B/비회원 데이터 격리는 아래 사항이 갖춰져야 완료 판정한다.

- **본 PR 정확한 HEAD**로 빌드한 개발 APK (기존 고정 개발키로 서명, 실제 `petworld-dev`용 최신 `google-services.json` 사용).
- 보호된 `petworld-dev-signing` Environment는 `main`만 허용하므로 Draft PR에 비밀값을 푸는 우회는 하지 않는다. 배포 없는 안전한 별도 서명 검증 환경/사용자 승인 워크플로가 필요.
