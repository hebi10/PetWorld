# FB-07-C2-C2-02 — 비공개 스케줄러 및 지속 체크포인트

선행 #75 HEAD 8c6afe63fd208b6c77aac62c21e763805cd55494. 실제 스케줄 등록·사용자 데이터 삭제·배포 없음.

- account-deletion-scheduler.mjs: Admin 전용 accountDeletionScheduler/v1 한 문서에 cursor, lease ID, lease 만료, 관측 시각을 트랜잭션으로 관리한다. 동일한 작업 동시 실행을 방지하고, 새 실행은 기존 cursor부터 진행하며, cursor 갱신은 정확히 일치하는 유효한 lease에서만 허용한다. SDK 실패·timeout·프로세스 중단·응답 유실 시 커서를 임의로 넘기지 않는다. 트랜잭션 응답이 유실된 경우 다음 호출에서 실제 저장 상태가 기준이다.
- 기존 내부 batch(최대 10건, 60초 동안 다음 작업 시작 제한)를 재사용한다. 보존 검증 대기 및 일시 실패는 전체 순회 후 다시 검토한다. 계정별 20분 lease/CAS 및 UID 범위·보존 감사 유지. 상위 scheduler lease는 25분, 외부 강제 종료 deadline은 최대 10분으로 가정하고, deadline을 넘긴 결과의 cursor 갱신을 거부한다. 실패 후 보수적으로 lease 만료까지 재실행을 유예한다. Promise timeout은 SDK 작업을 취소하지 않으므로 실제 실행 프로세스 hard timeout 및 clock 검증이 반드시 선행되어야 한다.
- prepareDeletionWorkerRuntime은 기존 dev 프로젝트/버킷, Rules, IAM, 보존 감사, HTTP admission, scheduler 및 SDK cache 조건을 재사용한다. prepareDevDeletionScheduler는 별도 private worker 초기화만 제공하며 TLS 인증서나 공개 HTTP 경로에 의존하지 않는다. scheduler 저장소·worker identity·hard deadline·clock 검증을 추가로 요구한다. 실제 Cloud Scheduler/Cloud Run 등록, 자동 실행, 운영 credential, schedule interval 지정 없음.
- 서버/앱 작업 상태는 분리한다. CHECKPOINTED는 해당 배치의 cursor 저장만 의미하고 모든 계정의 삭제 완료를 의미하지 않는다. aggregate만 반환하며 UID, job cursor, lease, ticket은 공개하지 않는다.
- 테스트: 합성 9건(동시 실행, cursor 복구, 순회, 만료, stale lease, deadline, 장애, 응답 유실, bootstrap gate) 및 Emulator 2건(클라이언트 접근 금지, 로컬 demo Admin Firestore 실제 동시 트랜잭션/복구). 실제 Firebase worker service account·IAM, Firestore query/index, hard process termination, clock skew, 보존 감사 및 격리 개발 계정 E2E는 미검증. 현재 scheduler는 등록/실행되지 않음.
