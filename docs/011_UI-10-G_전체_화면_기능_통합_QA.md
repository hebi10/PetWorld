## 3. 신규 API 29/35/36 실제 계측 매트릭스

`.github/workflows/android-ui10g-integration-qa.yml`이 GitHub Actions에서 앱 Debug APK와 계측 APK를 같은 정확한 PR 소스로 빌드하고 API 29·35·36 각각을 에뮬레이터로 실행한다.

| API | Android 계측 | 라이트·다크 원본 | 암호화 복원 |
| --- | --- | --- | --- |
| 29 | 기록 목록/기간·유형 필터 | 각 5개 화면 PNG 검사 | 성공·암호 오류·중단 복구 세 테스트 |
| 35 | 기록 목록/기간·유형 필터 | 각 5개 화면 PNG 검사 | 성공·암호 오류·중단 복구 세 테스트 |
| 36 | 기록 목록/기간·유형 필터 | 각 5개 화면 PNG 검사 | 성공·암호 오류·중단 복구 세 테스트 |

- `run-petworld-ui10g.sh`: `getprop ro.build.version.sdk`를 기대 API와 일치하는지 검증, 앱·테스트 APK 설치, `PetWorldRecordListCaptureTest`(1 테스트), `BackupRestoreDeviceTest`(3 테스트)를 각각 실행.
- `OK (1 test)`와 `OK (3 tests)` 확인, 라이트·다크 기록 목록 PNG 각각 5장 존재 확인.
- 실패 시 logcat·instrumentation.log·기기 표시 설정·스크린샷을 해당 API artifact에 저장.
- GitHub Actions source SHA를 `source-sha.txt`에 기록. 해당 Job의 `success`와 샘플 PNG·원본 SHA를 대조하여 최종 평가.

## 5. 종료 판정 규칙

**GO (UI-10-G QA):** 모든 이번 단계 필수 CI/API 29·35·36 Job 성공, API35 전체 화면 및 Fold/160% QA 녹색, 원본 아티팩트 무손상 확인, PR 변경 범위·데이터/Play 안전 검토 통과.

**조건부 GO:** 실기기 TalkBack, 실제 시스템 Photo Picker, 물리 Fold 연속 전환 등 자동화가 못 확인한 항목은 `UI-10-H` 배포 전 남은 실기기 QA로 관리한다. 자동화 성공을 모든 실제 기기 통과로 표시하지 않는다.

**NO GO:** 필수 빌드·계측 실패, 원본 데이터/복원 회귀, 기록 누락 또는 UI 버튼 접근성 실패. 이 경우 실패를 재현해 수정하고 동일 SHA 기준 재실행한다.

**안전 정책:** `main` 및 기존 Play 트랙은 이번 QA로 변경하지 않는다. 새 PR은 Draft로 유지하고 UI-10-H 통합 검수 전 자동 병합/배포 금지.
