# PetWorld | 001 기능 요구사항 명세
> 기준일: 2026-11-09 (KST) · 상태: 0단계 제품 기준선 v1.0 · 대상: Android 네이티브 앱

## 1. 목적과 기본 원칙
- **제품 정의:** 한 마리 이상 반려동물의 일상·건강·진료·지출·공동 돌봄을 개체별로 기록하고, 생활 변화를 관찰하는 생활 관리 앱.
- **대상:** 고양이·강아지 보호자, 다묘·다견 가정, 복약 및 진료 기록이 필요한 보호자, 가족 돌봄자.
- **핵심 목표:** (1) 반려동물 혼동 없는 기록 (2) 빠른 입력 (3) 누락과 변화의 정확한 표시 (4) 추후 공동 돌봄의 안전성.
- **의료 경계:** 앱은 사용자가 입력한 관찰 이력을 정리할 뿐 질병 진단·처방·약물 용량 결정·응급 판단을 수행하지 않는다.
- **개발 원칙:** 로컬 우선, 기본 기능 로그인 불필요, 계정/클라우드/AI는 개별 동의 후 선택 적용, 사용자 데이터 변경과 권한을 예측 가능하게 처리한다.

## 2. 기능 범위와 릴리스 정책
- **MVP — 필수 / 1~2단계:** 다중 프로필, 홈, 빠른 입력, 식사·음수·배변·활동·체중, 기록 조회·수정·삭제, 체중 및 생활 기본 추이, 로컬 보존과 백업·복구, 라이트/다크/시스템 모드.
- **확장 1 / 3~4단계:** 증상 일지, 진료·검사, 복약, 예방접종/검진 일정, 알림, 지출 관리, 기간별 분석과 내보내기(PDF 포함).
- **확장 2 / 5단계:** 계정·가족 초대·역할 권한, 여러 기기 동기화, 변경 이력과 충돌 해결. 기본 로컬 사용을 방해하지 않는다.
- **확장 3 / 6단계:** 성장 앨범·다이어리, 선택형 AI 관찰 요약.
- **공통 출시 검증 / 7단계:** 권한·접근성·상태 화면·테스트 기기·데이터 복구·Play 준비.
- **범위 제외:** 진단, 치료 권고 및 복용량 자동 산정, 웨어러블에서 자동 계측했다고 오인시키는 데이터, 불필요한 구독/결제, 자동 원격 업로드.
- **원칙:** 이후 단계의 화면·모델은 미리 설계하지만 MVP에 구현된 것처럼 노출하지 않는다.

## 3. 공통 정책: 기록과 시간
- 모든 영속 기록은 petId(필수 UUID)를 가진다. 선택된 반려동물과 실제 저장 대상은 저장 직전까지 화면에 명시한다.
- 기록 공통 메타: id, petId, recordType, occurredAt(UTC), timezoneId(입력 당시), createdAt/updatedAt(UTC), 작성자/입력 출처, memo, attachments, deletedAt(선택).
- 입력 시간 기본값은 현재 시각이며 과거 시각으로 변경할 수 있다. 미래 시각의 일상 실측 기록은 원칙적으로 경고·확인 후에만 저장한다. 예약 이벤트는 별도 모델이다.
- 일/주/월 그룹화는 기록 당시의 timezoneId로 계산한다. 사용자 단말 시간대 변경으로 과거의 날짜가 조용히 이동해서는 안 된다.
- 숫자는 화면에서 지역화해 입력하고 내부에서는 소수 오차가 없는 정수 최소 단위 또는 명시적인 Decimal로 관리한다. 체중 기본 단위 kg(저장 g), 음수 mL, 급여 g(액상은 mL 선택), 활동 분, 지출 KRW.
- 측정하지 않은 값은 0이 아니라 NULL/미측정으로 저장한다. 누락 기간에는 ‘기록 없음’과 ‘0’을 구분한다.
- 수정·삭제는 해당 그래프·합계·알림 상태를 즉시 재계산한다. 수정 전에는 대상과 기록 시각을 확인한다.
- 동일 개체·종류·시각·수치의 연속 중복 입력이 감지되면 중복 가능성을 안내하되 사용자 선택으로 저장 가능하다. 자동 삭제하지 않는다.
- 삭제는 명시적 확인과 즉시 실행 취소(가능한 경우)를 제공한다. 프로필 삭제는 연관 데이터 수를 알려준 뒤 이중 확인하며 기본 동작은 프로필 보관/비활성화로 둔다.

## 4. 기능 요구사항
### FR-01 다중 반려동물 프로필 — MVP / P0
- 이름 필수, 사진/종/품종/생일(또는 추정 나이)/성별/중성화/주의사항 선택.
- 종은 CAT/DOG/OTHER이며 OTHER의 종별 화면은 공통 기능만 제공. 생일 미상 및 대략적인 나이를 구분 저장.
- 프로필 추가·편집·보관, 프로필별 표시할 기록 항목 설정.
- 모든 입력 화면에 현재 동물의 이름/사진을 표시. 프로필 전환 시 기존 편집 중 내용을 무단 저장하지 않고 유지 또는 폐기 확인.
- 완료 기준: 동물 2마리 이상을 전환하며 기록, 통계, 백업이 섞이지 않는다.

### FR-02 홈 대시보드·빠른 입력 — MVP / P0
- 고정된 반려동물 전환 영역, 날짜, 오늘의 입력 현황, 기록 바로가기, 최근 기록, 예정된 돌봄(해당 단계 제공 범위)을 표시.
- 최근 기록/예정된 항목/미기록 항목은 서로 다른 상태로 표현. 미기록은 ‘미수행’으로 단정하지 않는다.
- 주요 일상 기록은 홈에서 기록 종류 선택 포함 2회 이내의 진입 동작으로 입력 화면 접근.
- 데이터 없음/선택 프로필 없음/저장 실패의 개별 UI를 제공.

### FR-03 식사·사료 기록 — MVP / P0
- 종류(사료/습식/간식/기타), 제품명(선택), 제공량(필수, >0), 실제 섭취량(선택, 0 이상/제공량 이하), 단위(g/mL), 시각, 담당자(로컬 단계에서는 나).
- 실제 섭취량 미기재는 ‘알 수 없음’으로 취급하며 제공량을 섭취량으로 자동 복사하지 않는다.
- 제품은 선택적으로 재사용할 수 있게 설계하되 별도 제품 카탈로그 편집은 확장 가능 모델로 둔다.
- 날짜별 합계는 제공량과 섭취량을 별도 시리즈로 표시한다.

### FR-04 음수량 기록 — MVP / P0
- mL와 시각, 메모 입력. 여러 반려동물이 공동 음수대를 사용하는 경우 특정 개체의 섭취로 추측해 분배하지 않는다.
- 마신 양을 알 수 없는 경우 별도 ‘미측정’ 상태; 통계 계산에서 제외한다.
- 일별 합계와 기록 횟수, 주간/월간 추이를 제공.

### FR-05 배변 기록 — MVP / P0
- 소변/대변 구분, 횟수(기본 1), 시각, 관찰 상태/메모, 사진(선택·후속 첨부 가능).
- 고양이 화장실/강아지 산책의 맥락은 선택 항목으로 제공하며 진단성 표현을 피한다.
- 횟수와 관찰 메모는 개별 집계. 없는 날짜를 ‘배변 안 함’으로 판단하지 않는다.

### FR-06 생활·활동 기록 — MVP / P0
- 산책/놀이/수면/기타, 시작시각, 지속시간(>0), 메모. 종료 시각은 시작+지속시간과 일치하도록 계산한다.
- 고양이는 놀이/수면을, 강아지는 산책/야외 활동을 기본 바로가기로 제공하며 모두 사용자 설정에서 조정 가능.
- 겹치는 활동을 원칙적으로 허용하되 이상한 중복에 대해서만 경고한다.

### FR-07 체중 기록 — MVP / P0
- 측정값(>0, 단위 kg/g), 측정 날짜·시각, 메모, 수정·삭제.
- 저장은 g 정수로 정규화하되 표시 정밀도와 원래 입력 단위를 함께 보존한다. 극단값은 입력 실수 가능성만 경고한다.
- 측정 시점 연결선 그래프, 기간별 변화량, 데이터 개수. 값 없는 날은 0kg로 표시하지 않는다.

### FR-08 기록 타임라인·검색·통계 — MVP / P0
- 동물/일자/유형별 필터, 최신순 타임라인, 기록 상세와 수정/삭제, 사용자가 입력한 값 그대로 표시.
- 최근 7일/30일/직접 지정 기간의 합계·건수·추세. 1개 값만 있을 때 증감률 또는 평소 대비 변화 확정 금지.
- 데이터 부족·서로 다른 단위·누락·미측정이 있는 경우 설명 문구 표시.

### FR-09 로컬 저장·백업·복구 — MVP / P0
- Room 저장, 앱 재실행/네트워크 단절/프로세스 종료 후 보존. DataStore에는 테마·선택 프로필·입력 기본값 등 설정만 저장.
- 백업은 사용자 실행 방식으로 로컬 데이터·선택한 첨부를 내보내기. 이식 가능한 암호화 패키지와 파일 무결성 검사·스키마 버전을 갖춘다.
- 복구는 파일 선택→암호 확인→지원 버전/무결성 검사→변경 결과 미리 보기→기존 데이터 전체 교체 확인→원자적 적용 순서.
- 복원 오류 시 기존 데이터는 변경하지 않는다. 앱 제거 및 기기 교체 시 로컬 데이터 자동 보존을 보장한다고 표현하지 않는다.
- 이미지의 원본 접근 권한이 사라질 수 있으므로 선택한 프로필 사진/첨부는 앱 내부 복사 정책을 사용한다. 외부 저장소 전체 읽기 권한 요구 금지.

### FR-10 건강 증상 일지 — 확장 1 / P1
- 구토/설사/식욕 저하/기타 사용자 정의 관찰, 시각, 지속·정도 메모, 사진을 개체별 기록.
- 증상 기록의 강도는 보호자의 주관 입력임을 표시. 의료 위험 점수나 병명 추천 금지.

### FR-11 병원·진료·검사 이력 — 확장 1 / P1
- 병원명, 방문일, 방문 사유, 진료 요약, 검사 수치/설명(자유 입력), 처방 메모, 영수증/문서 첨부.
- 특정 증상 및 복약 계획과 관련 링크로 연결. 원본 첨부와 입력 메모를 구분한다.

### FR-12 예방 관리 — 확장 1 / P1
- 예방접종·검진·구충 등의 계획, 예정일/완료일, 반복 규칙(선택), 알림, 이력.
- 사용자가 직접 설정한 날짜만 알림으로 쓰며 종별 의학적 권장 주기를 앱이 임의 확정하지 않는다.

### FR-13 복약 관리 — 확장 1 / P1
- 약 이름, 보호자가 확인한 투약 방법 메모, 시작/종료일, 일정·반복, 예정 회차별 완료/건너뜀/미확인 상태, 담당자.
- 회차별 고유 키(planId + scheduledAt + 규칙 버전)를 사용해 같은 회차의 중복 완료를 차단.
- 앱에서 약물 용량을 계산하거나 변경을 추천하지 않으며, 놓친 용량의 보충 투약을 자동 권유하지 않는다.
- 공동 돌봄 단계에서는 다른 담당자 완료 정보를 중복 처리 없이 보여준다.

### FR-14 반려동물 가계부 — 확장 1 / P1
- 반려동물·날짜·금액(KRW, >0)·분류(사료/진료/용품/미용/기타)·메모·영수증.
- 월별 지출, 분류별 합계, 반려동물별 총액. 미지정 공용비는 ‘가구 공용’으로 구분하고 자동 안분하지 않는다.

### FR-15 기간별 요약·리포트 — 확장 1 / P1
- 기간, 대상 동물, 포함 유형을 선택해 입력 사실 기반 보고서 작성.
- 식사/음수/체중/증상/복약/진료 흐름 및 누락 구간 표시; 차트와 원시 기록, 생성 시각 포함.
- 보호자가 검토 후 PDF/공유용 파일로 내보냄. AI 자동 작성이 있다면 문장과 원자료의 차이를 확인 가능해야 함.
- 의료진 판단을 대신하는 결론을 생성하지 않는다.

### FR-16 가족 공동 돌봄·동기화 — 확장 2 / P2
- 소유자(owner)/돌봄자(editor)/열람자(viewer) 권한: owner는 초대/추방·정책 관리; editor는 허용 기록 생성/수정; viewer는 열람만.
- 초대 수락·취소·탈퇴·권한 변경, 최근 수정자·변경 시각, 동기화 상태·충돌 안내.
- 클라우드 사용 전 명시적 로그인/동의, 기기별 동기화/오프라인 큐, 접근권한 변경 후 재인증 및 캐시 접근 차단.
- 복약 회차의 동시 완료 충돌은 서버에서 유일성 보장, 다른 기록 충돌은 덮어쓰기 전 비교·선택 제공.

### FR-17 성장 앨범·다이어리 — 확장 3 / P2
- 반려동물별 사진과 사건의 날짜별 타임라인, 제목·메모, 원본 파일의 존재/누락 상태 처리.
- 앨범과 기록 연결 및 선택적 공유. 사진 메타데이터(위치 등)와 계정 공유 권한을 별도 검토한다.

### FR-18 AI 관찰 보조 — 확장 3 / P3 (선택)
- 사용자가 선택한 기간의 기록과 평소 데이터의 차이를 근거 수치와 함께 ‘관찰 후보’로 요약.
- 기록 미존재·불충분·입력 오류 가능성과 사실/추정을 분리 표시. 오진 및 치료 지시 금지.
- 기본 비활성화. 로컬/원격 처리 방식, 비용, 데이터 전송 범위, 동의 철회·삭제를 별도 설정으로 제공한다.

## 5. 상태·오류·권한 계약
- 데이터 상태: loading / empty / content / error / permission-denied / offline / sync-pending / conflict; 화면은 해당 단계에서 지원하는 상태만 노출.
- 기록 상태: 작성 초안 → 검증 통과 → 저장됨 → 수정됨/삭제됨. ‘저장 완료’는 DB 트랜잭션 성공 후에만 안내.
- 일정 상태: upcoming / done / skipped / unconfirmed / canceled. 시간이 지났다는 이유만으로 보호자가 실제 투약·돌봄을 하지 않았다고 단정하지 않는다.
- 알림 거부에서도 앱 내 일정 조회·완료 기능은 정상. 미디어 권한 거부에서도 사진 없이 기록 가능.
- 데이터베이스 오류/기기 저장공간 부족/백업 손상 시 기존 자료가 손실되지 않도록 실패 경계를 둔다.

## 6. 품질·개인정보·접근성
- Android Kotlin + Jetpack Compose / MVVM·단방향 상태 흐름 / Room·DataStore를 기본 구성으로 제안(코드 미구현).
- 로컬 우선: MVP 데이터 생성·조회·수정·삭제는 네트워크 접속 없이 정상 동작해야 한다.
- 접근성: 글꼴 확대 160%, 화면 읽기 이름·상태, 충분한 터치 대상 크기, 색상에만 의존하지 않는 상태 구분.
- 라이트/다크/시스템 테마, 전화 세로형·작은 화면·태블릿·폴더블 레이아웃 고려.
- 원칙적으로 전체 사진 라이브러리 권한 대신 시스템 Photo Picker/파일 선택기를 사용한다.
- 복약과 예방 일정의 정시 알림은 OS 권한·배터리 정책 제약이 있으므로 ‘정시 보장’으로 표시하지 않는다. WorkManager만으로 초단위 정확 알림을 보장해서는 안 된다.
- 개인정보: 로그인 강제 금지, 데이터 삭제/내보내기, 클라우드 동의 분리, 최소 권한, 민감 내용이 잠금 화면 알림에 노출되지 않도록 옵션 제공.
- 로깅: 개인 사진·병원자료·약 이름·메모 원문을 분석 로그/오류 수집에 수집하지 않는다.

## 7. MVP 검수 필수 시나리오
1. 새 설치→동물 2마리 생성→서로 다른 식사/체중 입력→재시작→각 기록이 분리됨.
2. 제공량 50g·섭취량 미상인 식사는 ‘50g 섭취’로 집계되지 않음.
3. 음수 미측정/기록 없는 날은 0mL로 오표기되지 않음.
4. 배변·활동·체중 기록 수정/삭제 직후 기간별 합계와 그래프가 일치함.
5. 편집 중 반려동물 전환/뒤로가기 시 미저장 변경 안내가 나타남.
6. 네트워크 차단 상태에서도 MVP 전 과정 사용 가능.
7. 앱 강제 종료 후 저장 자료 보존; 백업/복구 암호·무결성·중단 복구 테스트 통과.
8. 알림/사진 권한을 거부해도 일상 입력은 동작.
9. 라이트·다크·시스템, 작은 화면, 글꼴 160%, 태블릿에서 CTA 잘림 없음.
10. 종별 선택 항목을 변경해도 기존 기록은 삭제되지 않음.

## 8. 확정된 기준과 후속 디자인 항목
- 기능 목록과 단계 배분, 입력 필수값·미측정 처리·반려동물 고정 컨텍스트·로컬 우선 정책을 0단계 기준선으로 사용한다.
- 최종 브랜드 심볼/아이콘 자산, 실제 컬러 토큰·타이포그래피 수치, 로컬 백업 UX 시안, 모바일/태블릿 시각 목업은 1단계 디자인 시스템 및 구현 과정에서 확정한다.
- 상용 출시 전 개인정보처리방침, Play 데이터 보안 양식, 알림 권한 정책, 접근성 및 저장소 마이그레이션은 별도 검증한다.
