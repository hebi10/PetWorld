## 0. 판정 범위 및 기준

본 평가는 **실제 Android 캡처를 직접 열어** 레이아웃, 밀도, 간격, 서체, 라이트/다크, 모달을 육안 평가한 내용입니다. 전용 고충실도 화면별 목업은 Drive에서 확인되지 않았고, 위 001/002/004/005 문서의 정보 구조·디자인 토큰·저충실도 와이어프레임을 비교 기준으로 사용했습니다.

**증거 수준:** 화면에 실제 보이는 문제 = 확인 / 제스처·키보드·160% 글꼴·태블릿·TalkBack = 캡처만으로 미검증. 일부 화면은 스크롤 중 특정 순간만 담았으므로 화면 하단에 없다는 이유만으로 기능 미구현이라고 판단하지 않습니다.

- **P1:** 홈의 프로필 카드·5개 기록 카드로 '최근 기록'이 첫 화면 아래로 밀림. 기획 W01의 조밀한 요약 배치와 불일치
- **P1:** 신규 프로필 화면은 아무 입력 전에도 '이름 (필수)' 테두리·문구가 오류색으로 표시되어 조기 오류처럼 보임

- **P1:** 통계는 화면 상단에 식사·음수·배변·활동 대형 카드가 먼저 보여 체중 추세 시각화·기간별 변화 판단이 어렵게 시작됨

## 3. 6개 축별 진단

### 레이아웃

- 상단 브랜드와 시스템 상태 표시줄의 충돌이 가장 심각한 시각·접근성 문제. Android edge-to-edge의 statusBar inset, topBar padding, system bar icon luminance를 고정
- 홈은 '프로필 → 오늘의 돌봄 → 최근 기록' 순서를 지키지만 **오늘의 돌봄 5종을 전부 독립 대형 카드**로 표현해 한눈에 보는 의미가 약함
- 설정·프로필 관리는 작업 목록 대비 과도한 카드 높이, S14 통계는 그래프가 뒤로 밀림
- 폴더블/태블릿 2열은 이번 1080×2400 휴대폰 캡처로 검증할 수 없음

### 정보 밀도

- S03: 현재 주의사항은 크고, 최근 실제 기록은 화면 밖
- S11: 2개 필터 줄 + 넓은 레코드 카드가 목록 정보량을 잠식
- S16/S30: 중요한 기능 접근보다 큰 안내 카드·광폭 버튼이 우선 노출
- 기획 정보 구조를 훼손하지 않으면서 **정보 요약 영역의 밀도만 높이는 정밀 보정** 권장

### 간격

- 가로 여백은 대체로 일정하고 충분함
- 세로로 반복되는 16~24dp 이상의 간격·카드 내부 패딩 때문에 화면 1장의 스크롤 비용이 큼
- 기록 폼은 칩·텍스트필드·날짜/시간을 연속 배치하되 라벨과 값의 간격 계층을 정리
- 명목 48dp 터치 범위는 코드 기준이나 손가락 접근성·160% 글꼴은 별도 기기 검증 필요

### 타이포그래피

- 한글 헤드라인 대비가 강하고 '나비의 하루' 등 정보 계층은 분명함
- 제목·카드 제목의 시각적 중량이 반복되어 보조 기록 값보다 먼저 보임. 세부 정보의 우선순위를 조정
- 식사량/음수량/체중 숫자는 크기·단위를 한 쌍으로 묶고, 날짜/메모는 보조색 유지
- 초기 필수 입력에 오류색 적용한 S02는 오류 시맨틱의 오용이므로 우선 수정

### 라이트·다크

- 흰 배경과 거의 검은 텍스트 / 차콜 배경과 흰 텍스트, 직각 윤곽 카드가 두 모드에서 일관됨
- **다크 시스템 상태 표시줄의 어두운 아이콘**과 최상단 브랜드 마크 겹침: 단색 시스템 바 처리 오류 가능성이 높음
- 선택된 필터·라디오 버튼은 색 대신 밝은 채움/윤곽·상태 아이콘으로 구분되어 양호
- `S31`의 다크 파일 선택기는 OS DocumentsUI의 밝은 테마이므로 앱 자체 다크 정책 불이행으로 단정할 수 없음

### 모달·시트

- S04 전환은 현재 선택 체크·다른 프로필 목록·추가/관리 액션이 명료
- S05 빠른 기록은 5개 전체폭 버튼에 과도한 공간을 사용하고 닫기 액션이 약함
- 삭제 확인은 회복 불가능한 행동을 명시해 안전성 양호
- 백업 암호 모달은 입력 구조가 명확하지만 키보드가 켜진 좁은 화면·오류 상태 검증 필요
- 복원 파일 선택기의 라이트 캡처가 실제 DocumentsUI가 아니므로 해당 비교는 보류

- 홈 '최근 기록', 통계 그래프, 설정의 페이지 하단은 스크린샷의 visible viewport만으로 완료 여부를 단정하지 않고 추가 스크롤 캡처 필요
- 이 문서는 분석 결과이며 실제 앱 UI 변경·PR 병합을 수행하지 않음

## 6. UI-01 수정 구현 기록

- **증상:** 상단 PetWorld 워드마크가 Android 상태 표시줄 시간/아이콘과 겹침. 앱 강제 다크 모드에서 상태 아이콘 색상도 기기 시스템 테마 기준으로 남을 수 있음
- **수정 범위:** 공통 `PetWorldNavigation.kt`의 `Scaffold.topBar`에 `Modifier.statusBarsPadding()` 추가, `MainActivity.kt`에 `WindowCompat.getInsetsController` 기반 시스템 바 아이콘 모드 동기화
- **보존 범위:** 기존 상단 로고 크기, 헤더 2행 구조, 하단 5탭, 카드/글꼴/여백 토큰 및 저장 로직은 변경하지 않음
- **자동 검증:** `PetWorldScreenCaptureTest`에서 온보딩·홈의 브랜드 레이블 위치가 시스템 상태 표시줄 아래인지 확인하고 앱 라이트/다크 설정과 상태 바/내비게이션 아이콘 밝기 설정 일치를 검증
- **출시 기준:** Android CI와 API 35 라이트/다크 캡처 QA가 모두 통과하고 실제 PNG 상단의 겹침·아이콘 대비가 없는지 확인해야 완료 처리

## 7. UI-02 구현 기록 — 홈 카드 압축 및 최근 기록 가시성

- **범위:** S03 `PetHomeScreen`과 홈 탭의 섹션 간격만 변경; 다른 4개 탭과 기록 저장 기능은 유지
- 프로필 사진 72dp → 48dp, 프로필 수정 버튼을 텍스트 버튼으로 축소, 주의사항을 최대 두 줄로 제한
- 식사/음수/배변/활동/체중 개별 5개 카드 → 하나의 경계선 카드에 5개 목록 행. 각 행은 48dp 이상 터치, 아이콘·유형·실제 요약값·건수 표시
- 기존 `summarizeCare` 로직을 재사용하여 미기록·미측정·확인된 0의 데이터 의미를 유지, 각 행 선택 시 해당 기록 필터로 이동
- 홈 탭의 섹션 간격 24dp → 12dp, '최근 기록' 제목을 앞쪽으로 이동. 최근 기록은 기존 날짜 내림차순 5건과 상세 진입 유지
- 불필요한 추가 라이브러리·색상·장식·애니메이션 도입 없음
- 화면 QA 테스트에 `최근 기록` 노출 확인 추가. 실제 Android API 35 라이트/다크 캡처와 CI 통과 여부에 따라 완료 판정
- 작은 화면 360dp, 160% 글꼴, 데이터 긴 이름·요약값의 말줄임 및 접근성은 별도 QA 필요
